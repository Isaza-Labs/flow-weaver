# Contributing to FlowWeaver

Thank you for helping improve FlowWeaver. The project is owned and stewarded by **Isaza Labs LLC** and is licensed under Apache License 2.0.

Submission and provenance details are in [legal/CONTRIBUTION_TERMS.md](./legal/CONTRIBUTION_TERMS.md), including the verbatim DCO 1.1 text.

## Contributions we accept

- Code fixes and improvements.
- Tests and QA evidence.
- Specs and integrations.
- Skills and reusable workflows.
- Documentation and examples.
- Bug reports and feature requests.

Open an issue before substantial or security-sensitive changes so scope and acceptance criteria can be agreed.

## License of contributions

Unless you conspicuously state otherwise, a contribution intentionally submitted for inclusion in FlowWeaver is provided under Apache License 2.0, without additional terms, as described in section 5 of that license.

By submitting a contribution, you confirm that you have the right to do so and that third-party material is identified with its source and license.

## DCO sign-off

Every commit must carry a Developer Certificate of Origin sign-off:

```bash
git commit -s -m "Describe the change"
```

The resulting `Signed-off-by` line certifies that you may submit the work under the project license. Configure your real `user.name` and `user.email` before committing.

## Pull request checklist

- Keep the change focused.
- Link the related issue.
- Include or update tests when behavior changes.
- Update documentation and examples when interfaces change.
- Identify modified third-party code and preserve its notices.
- Record third-party assets, datasets, models and generated material under the applicable intake policy.
- Do not include secrets, customer data or internal evidence.
- Confirm DCO sign-off on every commit.

## Development setup

Follow the [quick start](./QUICK_START_GUIDE.md) for setup and the [frontend guide](./frontend/README.md) for UI commands. Use the test commands in the quick start and report which checks you ran in the pull request.

## Security

Do not disclose vulnerabilities in public issues. Follow [SECURITY.md](./SECURITY.md).

## Contribution agreement status

No separate CLA is required. Contributions use Apache 2.0 and DCO sign-off as described above.
